## Mandate

A UK supermarket chain. A software developer role centred on interactive
reporting: replacing static, pre-generated reports with a self-service suite the
business could query itself, and supporting the systems running in branch.

## Achievements

- **Built an interactive self-service reporting suite** `#data` `#frontend`
  - What: replaced existing static reports with dynamic self-service reporting,
    so the business could answer its own questions rather than requesting a
    report and waiting for it
  - How: a single-page store ordering web application built with Backbone.js
    and Marionette
  - Emphasise for: full-stack, data and reporting, internal tooling

- **Tuned MySQL to carry tables in excess of 300 million rows** `#data`
  - Metric: tables in excess of 300 million rows
  - What: optimised table structure and system configuration to cope at that
    volume
  - Emphasise for: backend, data engineering, any role naming database
    performance or query tuning

- **Aggregated data in-store before it reached the central API**
  `#architecture` `#data`
  - What: distributed the aggregation out to the stores, which then connected
    to a RESTful API, rather than shipping raw data centrally and aggregating
    there
  - Emphasise for: backend, architecture, distributed systems, edge processing

- **Built in-branch self-diagnostics for network faults** `#delivery`
  - What: detection for network faults in branch
  - Why it matters: an undetected network fault could stop a branch trading
  - Emphasise for: backend, reliability, operations, retail technology

- **Redesigned the Branch Backoffice UI to be responsive** `#frontend`
  - What: updated the HTML and CSS so the design would work on tablets in
    branch
  - Emphasise for: frontend, full-stack

- **Worked on card payment systems inside PCI scope** `#security` `#data`
  - What: branch systems took card payments, which brought the work inside PCI
    scope
  - Change: the business transitioned card payment provider during my time there
  - Contribution: exposure to the payment path and to the provider transition;
    neither was mine to own
  - Emphasise for: payments, fintech, and any spec naming PCI DSS or a regulated
    industry

- **Negotiated requirements directly with stakeholders up to board level**
  `#stakeholder`
  - Who with: stakeholders including the Board of Directors
  - Why it matters: direct board exposure in a developer seat, without a
    product or account layer in between
  - Emphasise for: any role with stakeholder, product or client-facing exposure

## Technical surface

- **Languages:** PHP, JavaScript
- **Front end:** Backbone.js with Marionette, jQuery
- **Datastores:** MySQL and PostgreSQL, with MySQL performance and tuning work
  at 300 million rows plus
- **Architecture:** RESTful API with aggregation distributed to the stores

## Tailoring notes

- **Leads for:** data volume and database tuning - the 300 million row figure is
  the hardest number in the early history
- **Also carries:** board-level stakeholder contact, unusually early in a career
- **Note:** the front-end stack here is dated. The reporting suite is worth
  describing by what it did rather than what it was built with, unless the
  target names Backbone
